### 3. 同款卖家 = 竞对核弹（企业主体 + 价格战）

`/modal/otherOffersFromSellers?product_id=<sku>&sort=price` → `webSellerList.sellers[]`：

- **一个 SKU 有 112 个卖家在卖**（实测）
- 每个卖家带：**企业凭据**（公司名/注册地址/国家/营业模式）+ 价格 + 配送承诺
- 实测全部是中国跨境公司：漳州（Zhaotuo）、厦门（Huimeifeng）、晋江（Fuyida）、阜阳（Liangaqi）、珠海（haoou）……
- `sort=price` 直接给价格战排序：193₽ → 201₽ → 204₽ → 212₽ → 215₽

→ 判断：**这个品是不是红海**（卖家数）、**最低价能不能打**（价格带）、**货源地**（供应链格局）。

## 三、选品工作流（建议）

```
1. 需求探测：autocomplete 种子词 → 联想词 + 关联类目 + 品牌（找增长方向）
2. 市场体检：类目页 filtersDesktop（垄断度/价格带/中货比/履约）+ 列表页价格分布
3. 竞对扫描：头部 SKU → otherOffersFromSellers（卖家数 + 企业凭据 + 价格带）
4. 实力评估：主要卖家店铺页（订单量/上新/品类广度）
5. 机会判断：
   - 卖家数 < 20 且价格带分散 → 蓝海
   - 卖家数 > 50 且价格带集中 → 红海（需差异化）
   - 全部中国货源 → 供应链竞争，拼履约/设计
```

## 四、类目 → 关键词（关联量实测）

### 两条路径

| 路径 | 数据 | 实测（解压玩具类） |
|---|---|---|
| 类目页自身 | title/h1 变体 | 仅 1-2 个（"Антистресс игрушки"） |
| **商品级聚合（推荐）** | 类目 → SKU → PDP2 → `webHashtags` + `tagList` | 见下 |

### 商品级聚合（`?layout_container=pdpPage2column&layout_page_index=2`）

每个商品的 PDP2 带：
- **`webHashtags.badges[]`：16 个可搜索标签**（#антистресс、#антистрессклавиатура、#кликер、#брелок…，点击跳 `/search/?text=`）
- **`tagList.items[]`：10 条 SEO 关联类目**（Брелоки для сумки、Звуковой брелок…，点击跳类目）

**5 个 SKU 聚合实测**：`webHashtags` 去重 **65 个** + `tagList` 关联类目去重 **17 个**（样本：`cat_keywords_agg.json`）

标签分 4 类（选品找词直接来源）：
1. **品类**：#спиннер 系列 15 个变体（спиннер/спинео/спинер/спиннеры…）
2. **场景**：#длядетей、#дляофиса、#вдороге、#длястудентов、#длядома
3. **功效**：#релаксация、#снятиестресса、#фокусировка、#концентрация、#калминг
4. **受众**：#длямальчиков、#длявзрослых、#для_малышей

**单类目总量估算**：SKU 数 × 16 标签，去重后（5 SKU→65 密度）→ **100~500 SKU 的类目可聚合出 400~1000+ 独特关键词**，加标题分词和关联类目更丰富。

## 五、附带发现（采集效率）

1. **列表页不查 PDP 即得价格/评分/评价数/促销/配送**——批量选品扫描成本极低
2. 翻页需带 `paginator_token` + `search_page_state`（服务端状态），不是简单 page=N
3. `Магазин` 筛选（key=seller）直接给类目头部店铺列表 + sellerId
4. 同款卖家 modal 的 `sort=price|date` 控制竞对排序
